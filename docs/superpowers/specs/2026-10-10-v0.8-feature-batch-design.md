# KMctrl 0.8 — feature batch design

Date: 2026-10-10. Status: draft for review.

## Goal

Make KMctrl comfortable for daily use as a bridge from a locked-down (MDM) work Mac to a
personal Mac, in **window mode** (no TCC permissions on the controlling side). Edge mode is
untouched by this batch — it needs permissions MDM blocks, so it is not the daily path.

Everything ships as one release (0.8.0) and is tested end to end afterwards on the real pair of
Macs. Items are built in the order listed so protocol changes land before features that use
them, and tests exist before the codec grows.

Out of scope (decided): launch at login (MDM may block it; double-click is fine), edge-mode
changes, file transfer, screen preview, full-system wake (Wake-on-LAN).

## Items

1. Bug: Magic Mouse horizontal swipe drops capture
2. Unit-test target
3. Keyboard-layout-independent typing
4. Media keys (volume, brightness, play/pause, …)
5. Mouse sensitivity
6. Re-grab hotkey
7. Wake the remote display
8. Update check (GitHub releases)
9. Clipboard sync (text + image)

## 1. Bug: Magic Mouse horizontal swipe drops capture

**Symptom.** While controlling in window mode, a horizontal swipe on a Magic Mouse ends
capture and control returns to the work Mac.

**Hypothesis** (to confirm first with systematic-debugging, instrumentation below). Window
mode ends capture on `NSApplication.didResignActiveNotification`
(`ControlHost.init`). A two-finger horizontal swipe on a Magic Mouse is the system "swipe
between full-screen apps" gesture. The Dock/WindowServer handles it before the app sees it,
switches Space, KMctrl's window is left on the old Space, KMctrl resigns active, capture ends.
A one-finger scroll only produces `.scrollWheel` events (already consumed), but may also
produce `.swipe` gesture events that the SwiftUI window could act on.

**Instrumentation (kept).** Log in the Diagnostics page: when resign-active fires during
capture, log the new frontmost app's name; subscribe to
`NSWorkspace.activeSpaceDidChangeNotification` and log it during capture. This makes the
cause visible on the user's Mac even if the hypothesis is wrong.

**Fix (three layers, all window-mode only).**

- Local monitor also matches `.swipe, .gesture, .magnify, .rotate, .smartMagnify,
  .pressure` while capturing and swallows them (returns nil), so no in-app gesture handling
  runs. These are not forwarded.
- While capturing, the main window's `collectionBehavior` gets `.canJoinAllSpaces` (and
  `.fullScreenAuxiliary`) so a Space switch keeps the window frontmost and KMctrl active;
  the previous behavior is restored on capture end.
- Resign-active during capture no longer ends capture immediately. It schedules a 250 ms
  grace check; capture ends only if `NSApp.isActive` is still false then. A genuine ⌘-Tab
  away still releases (just 250 ms later); a transient flicker caused by a gesture does not.

**Testing.** No unit test (AppKit). Manual: horizontal one- and two-finger swipe on Magic
Mouse, trackpad three-finger swipe, ⌘-Tab (must still release), Mission Control key.

## 2. Unit-test target

New `KMctrlTests` unit-test bundle (XCTest, hosted by KMctrl.app, `@testable import KMctrl`)
added to `KMctrl.xcodeproj` as a `PBXFileSystemSynchronizedRootGroup` at `KMctrlTests/`, with
a target dependency on KMctrl and the test target added to the shared scheme's TestAction so
`xcodebuild -scheme KMctrl test` runs it.

Tests cover pure logic only (no CGEvent/network/UI):

- `ControlEvent` binary codec: round-trip for every kind, `wireOrder` byte stability
  (snapshot of the table), rejection of wrong-size and unknown-kind frames, round-trip with
  and without the new `chars` trailer (item 3), and legacy 44-byte frames still decode.
- `ControlEventKind(wireByte:)` for out-of-range values.
- `AppSettings.clampedFlushInterval`, `AppSettings.clampedMouseSensitivity` (item 5).
- `ControlReturn` JSON: `pong` nil vs set.
- `KeyCharacters.override(for:flags:)` rule (item 3).
- `MediaKey` encode/decode of `data1` (item 4).
- `AppVersion` parsing and comparison (item 8).
- `ClipboardPayload` Codable and size-cap rule (item 9).

Pure helpers that items 3–9 introduce are written as small value types / static functions so
they are testable; the AppKit/CG glue around them stays thin.

## 3. Keyboard-layout-independent typing

**Problem.** `ControlEvent.keyDown` carries only the virtual key code. If the two Macs use
different keyboard layouts, the controlled Mac types what *its* layout maps that key to.

**Protocol.** `ControlEvent` gains `chars: String?` — the `NSEvent.characters` of the key
down, sent only on `.keyDown` and only when the override rule (below) says so. JSON: optional
field, absent when nil — byte-identical to today's frames when unused, so older peers keep
working on the JSON path. Binary: the fixed 44-byte frame gains an optional trailer
`charsLen[1] chars[charsLen]` (UTF-8, max 32 bytes; longer is dropped to nil). Receiver
accepts `count == 44` (legacy) or `count == 44 + 1 + charsLen`. An un-updated controlled Mac
receiving a trailered binary frame falls to JSON decode and the session drops — binary is an
experimental, default-off flag, and both Macs are expected to be on 0.8 to use it. Documented
in the README's binary-protocol note.

**Override rule** (`KeyCharacters.override(for chars: String, flags: UInt64) -> String?`,
pure):

- nil when ⌘ or ⌃ is held — shortcuts are keycode-based and apps match them on
  `charactersIgnoringModifiers`, which the override would corrupt (⇧ case).
- nil when `chars` is empty (dead keys), or any scalar is a control character (return, tab,
  delete, escape, arrows via their PUA code points U+F700–U+F8FF) — the key code already
  produces the right thing there.
- otherwise the string itself (plain typing, ⇧, ⌥ — ⌥ is exactly the layout-dependent case).

**Injection.** `ControlInjector.postKey` for a key down with `chars` present calls
`CGEvent.keyboardSetUnicodeString` on the event after setting flags, so the frontmost app on
the controlled Mac receives the controller's characters regardless of its own layout. Key
ups unchanged.

**Limitation (documented).** ⌘/⌃ shortcuts remain keycode-based, so e.g. ⌘Z on a layout where
Z sits elsewhere still fires the controlled Mac's own mapping.

## 4. Media keys

**Capture.** Local monitor mask adds `.systemDefined`. Events with `subtype == 8`
(`NX_SUBTYPE_AUX_CONTROL_BUTTONS`) are decoded by `MediaKey.decode(data1:)` → `(key, isDown,
isRepeat)` where `key = (data1 >> 16) & 0xFFFF`, `state = (data1 >> 8) & 0xFF` (0x0A down,
0x0B up), `repeat = data1 & 1`. Forwarded as `ControlEvent(kind: .mediaKey, keyCode: key,
button: isDown ? 1 : 0)`. `.mediaKey` is appended to `wireOrder` (byte 10). Repeats are
forwarded as downs (they arrive as such).

**Inject.** `NSEvent.otherEvent(with: .systemDefined, location: .zero, modifierFlags: [],
timestamp: ProcessInfo.systemUptime, windowNumber: 0, context: nil, subtype: 8,
data1: MediaKey.encode(key:isDown:), data2: -1)?.cgEvent?.post(tap: .cghidEventTap)`.
Both the down and the up are posted. Keys covered: volume up/down/mute, brightness
up/down, keyboard illumination up/down, play/pause, next, previous, fast/rewind.

**Known limitation (documented in Settings hint).** macOS handles volume/brightness keys
at system level before the app sees them, so the work Mac's own volume/brightness also
changes. Only an event tap (Input Monitoring) could suppress that — not available on MDM.

## 5. Mouse sensitivity

`AppSettings.mouseSensitivity: Double`, default 1.0, clamped to 0.25…3.0 by
`AppSettings.clampedMouseSensitivity`. Slider in Settings → Control ("Mouse speed",
0.25×…3×, step 0.25, with reset-to-1× button). `ControlHost.mouseSensitivity` mirrors it
live (AppModel subscribes to the published setting), and `translate()` multiplies mouse
dx/dy by it. Scroll is not scaled.

## 6. Re-grab hotkey

`AppSettings.regrabHotkeyEnabled: Bool`, default **on**. Fixed combo **⌃⌥⌘K**
(release stays ⌃⌥⌘ alone). Toggle in Settings → Control with the combo shown.

`HotkeyMonitor` (Carbon `RegisterEventHotKey` + `InstallEventHandler` on the application
target — no TCC permission, works in the sandbox and on MDM) is registered while the
setting is on and `ControlHost.state != .idle`, i.e. there is a session to re-enter.
Handler, on the main actor:

- state `.capturing` → ignore (⌃⌥⌘ already released capture a few ms earlier; see below).
- state `.connected` → activate KMctrl, bring its main window to front (open it if closed),
  then `beginCapture()`.
- A 400 ms debounce after `endCapture()` ignores the hotkey, because pressing ⌃⌥⌘K
  while capturing releases on the modifiers before K arrives; without the debounce the K
  would immediately re-capture.

No "connect to last peer from idle" — out of scope for this batch (the hotkey is for
re-grabbing an open session).

## 7. Wake the remote display

New `ControlEventKind.wakeDisplay` (wire byte 11), control-plane only (not injected via
CGEvent). The controlled Mac handles it by calling
`IOPMAssertionDeclareUserActivity("KMctrl remote input", kIOPMUserActiveLocal, &id)`,
which wakes a sleeping display and resets the idle timer. Sent automatically by the host
every time capture begins, and from a "Wake screen" button in the active-session card (and
menu bar while connected) for the case where the display sleeps mid-session. Older
controlled Macs ignore unknown JSON kinds? No — `ControlEventKind` is a `String` enum and an
unknown raw value fails to decode, which would kill the session. So the host only sends
`.wakeDisplay` when the peer's hello reports protocol version ≥ 2 (see Protocol version
below). Full system sleep is out of scope: an asleep Mac has no network.

## 8. Update check

`UpdateChecker` (main-actor `ObservableObject`): fetches
`https://api.github.com/repos/jbull79/kmctrl/releases/latest` with `URLSession`
(unauthenticated; 60 req/h is plenty), reads `tag_name` (e.g. `v0.8.0`), `html_url`, and
the first `.zip` asset's `browser_download_url`. `AppVersion` (pure) parses dotted
numeric versions with an optional leading `v` and compares numerically.

Schedule: 5 s after launch, then every 24 h while running, and on demand ("Check now").
Last-check time and last result cached in UserDefaults so a relaunch within 24 h does not
re-fetch. `AppSettings.updateCheckEnabled: Bool`, default on, toggle in Settings → General
("Check for updates on GitHub daily").

UI: Settings → General shows "KMctrl 0.7.1 · up to date / 0.8.0 available [Download]
[Check now]"; the menu-bar popover shows an "Update to 0.8.0…" row when one is available.
Download opens the asset URL in the browser (the app is unsigned; the user keeps doing the
`xattr` dance from the README). No self-update.

## 9. Clipboard sync

**Scope.** Mirror text and images between the two Macs **while a control session is active**,
both directions, trusted peers only. Files and other pasteboard types are not mirrored.

**Setting.** `AppSettings.clipboardSyncEnabled: Bool`, default on, toggle in Settings →
Control and in the menu-bar popover. Each Mac's own toggle gates both what it sends and what
it accepts. `StatusReport.clipboard` reports it.

**Transport.** A separate, short-lived `.clipboard` session per change — never on the control
stream, so a multi-megabyte image cannot stall mouse events. Sender: on pasteboard change,
`TransportConnector.connect(to: peer)` → handshake → `SessionHello(kind: .clipboard)` →
`ClipboardPayload` → close. Receiver (`ControlManager.handleIncoming`, new `.clipboard`
case): accept only if `clipboardSyncEnabled` and the fingerprint is trusted; otherwise close
silently. On accept, write to `NSPasteboard.general` (text as `.string`, image as `.png`)
and remember the resulting `changeCount` so the write is not echoed back.

**Peer resolution.** The host knows its `Peer`. The controlled side knows only
`link.remoteName`/fingerprint; it resolves the controller through the discovery list by name
and skips (with a Diagnostics log line) if the name is not discovered.

**Watcher.** `ClipboardSync` polls `NSPasteboard.general.changeCount` every 500 ms while a
session is active on either side (host `.connected/.capturing`, or `controlActiveFrom != nil`),
and stops otherwise. On change it reads `.string`, else `.png`/`.tiff` (TIFF converted to PNG
via `NSBitmapImageRep`). Caps: text 1 MB, image 8 MB (pure `ClipboardPayload.isWithinLimits`);
over-cap changes are skipped with a log line. A change whose `changeCount` equals the one we
just wrote is ignored (echo suppression). Sends are serialized; a change arriving while a
send is in flight is coalesced into one trailing send.

## Protocol version

`SessionHello.version` becomes 2 for `.control` hellos from 0.8. `ControlAck` gains
`version: Int = 1` (optional on decode, default 1) so the host learns the controlled Mac's
version. `.mediaKey` and `.wakeDisplay` are sent only when the peer's version ≥ 2; against
an older peer they are dropped with one log line per session. `chars` is dropped the same
way on the JSON path (it is harmless there, but keeps behavior explicit). Binary codec is
unchanged in its framing except the optional trailer (item 3).

## Settings and UI summary

- General: update row + daily-check toggle.
- Control: mouse speed slider; re-grab hotkey toggle (⌃⌥⌘K); clipboard sync toggle; media

- Menu bar: clipboard toggle, "Wake screen" while connected, update row when available.
